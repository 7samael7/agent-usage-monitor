# Adding a new AI application

An adapter answers one question: given a line an application wrote, what does it
tell us about token usage?

## The shape

```rust
pub trait UsageAdapter: Send + Sync + 'static {
    fn id(&self) -> AdapterId;

    /// Cheap byte test, run before any JSON parsing.
    fn is_candidate_line(&self, head: &[u8]) -> bool;

    /// The hot path. Pure and synchronous — no I/O.
    fn parse_line(&self, ctx: &mut LineCtx, line: &[u8]) -> ParseOutcome;
}
```

`parse_line` being pure and synchronous is a structural choice, not a style
preference. It means backfill can run on a blocking pool with no async overhead,
and every parser is testable against a fixture with zero runtime and zero setup.

Adapters emit `Signal`s and never touch the database, so a change to an
application's format breaks one parser and one set of golden tests rather than
the application.

## The rules that matter

**Never invent a number.** If a field is absent, the signal carries `None`, not
`Some(0)`. Claude Code reports no reasoning-token count; recording zero would
assert that no reasoning happened, which is a different and unsupported claim.

**Every field is optional, and unknown keys are accepted.** These are
undocumented formats belonging to tools that ship weekly. A parser that rejected
an unfamiliar key would start losing data the first time a field was added, and
losing data here is invisible until a total is wrong.

**Give each measurement a deduplication key.** Files get re-read — after a
crash, after a truncation, when backfill overlaps live tailing. The key is what
makes that safe. Claude Code has a request id; Codex has none, so its key is the
event's position in an append-only file.

**Be conservative in the prefilter.** A false positive costs one wasted parse. A
false negative silently loses a measurement.

**Report what does not add up.** A provider contradicting itself is a fact about
the data. Emit an `Anomaly` alongside the measurement rather than dropping the
row or quietly repairing it — an anomaly is enough on its own to stop a total
calling itself exact.

## Normalization

Do not invent a token model. `aum_domain::TokenUsage` is a disjoint partition
with private fields, and the only ways in are `from_anthropic` and
`from_openai`. If a new provider's semantics match neither, add a third
constructor beside them — that is the one place where a provider's conventions
are allowed to be encoded, and keeping it that way is what prevents the
double-counting mistakes that cost 145% and 24% in real data.

## Capabilities are observed, not declared

There is no place to write down what an adapter supports. The **Apps** tab is
generated by running the real parser over the application's own recent files and
recording which normalized fields real data populated, with the value that proved
each claim.

That means a new adapter needs no capability declaration at all — and it means
the matrix degrades honestly when a tool changes underneath it, instead of
asserting something that stopped being true.

## Testing

1. **Unit tests** on the parser, covering the awkward shapes: a failure marker,
   a line that is not a request, a field that is absent rather than zero.
2. **A golden fixture** from real data, put through `cargo xtask redact` *before*
   it enters the repository:

   ```bash
   make redact IN=~/.newagent/sessions/<file>.jsonl OUT=tests/fixtures/newagent/<name>.jsonl
   ```

   Compute the expected numbers independently of the parser, so the test checks
   it rather than merely recording it. If the new agent names its fields
   something the redactor has never seen, they are scrubbed by default; add them
   to `KEEP_KEYS` in `xtask/src/redact.rs` deliberately, one at a time, only for
   fields a test actually asserts on.
3. **An ignored real-corpus test** that runs against the machine's own files and
   asserts the properties that matter — that deduplication actually collapses
   something, that nothing fails to parse.

The third is what catches format changes. The first two only prove the parser is
self-consistent.

## Applications that cannot be measured

Add them anyway. Claude Desktop has an adapter whose every capability is
`Unsupported`, with the reason: it records only plan-limit percentages, and there
is no defensible transform from those to a token count. "Detected, nothing to
collect, and here is why, and here is what to use instead" is far more useful
than omitting it and leaving someone to wonder whether the monitor missed it.
